# Forum API

Backend-приложение форума, разработанное на **ASP.NET Core Web API**.

Проект представляет собой REST API для социальной платформы: пользователи могут регистрироваться и авторизовываться, создавать и просматривать публикации, работать со своим профилем и загружать аватар.

Основная цель проекта — практическая реализация backend-приложения с разделением ответственности между слоями, JWT-аутентификацией, работой с PostgreSQL и Redis, валидацией запросов, централизованной обработкой ошибок, логированием и контейнеризацией.

## Возможности

Реализованы:

* регистрация пользователей;
* авторизация с использованием JWT;
* получение данных текущего пользователя;
* получение и изменение профиля пользователя;
* создание публикаций;
* получение публикации по идентификатору;
* получение ленты публикаций с cursor-based пагинацией;
* получение публикаций конкретного пользователя;
* загрузка пользовательского аватара;
* выдача и кэширование изображений аватаров;
* ограничение частоты запросов для авторизации и загрузки файлов;
* централизованная обработка исключений;
* health check состояния приложения и базы данных;
* Swagger/OpenAPI-документация API;
* структурированное логирование.

## Основные API

### Аутентификация

```http
POST /api/auth/register
POST /api/auth/login
```

После успешной авторизации клиент получает JWT, который используется для обращения к защищенным endpoint'ам.

### Пользователь

```http
GET /api/users/me
GET /api/users/me/profile
PUT /api/users
```

Позволяет получить информацию о текущем пользователе, его профиль и изменить пользовательские данные.

### Публикации

```http
GET  /api/posts
GET  /api/posts/{id}
POST /api/posts
```

Для списка публикаций используется cursor-based пагинация.

Также можно получить публикации конкретного пользователя:

```http
GET /api/users/{userId}/posts
```

### Аватар

```http
POST /api/users/me/avatar
```

Endpoint позволяет авторизованному пользователю загрузить собственный аватар.

Для загрузки файлов настроены:

* ограничение размера запроса;
* rate limiting;
* проверка входных данных.

Получение сохраненного изображения выполняется через отдельный публичный endpoint:

```http
GET /api/files/avatars/{userId}/{avatarId}
```

Для изображений используются HTTP-заголовки кэширования и `ETag`.

## Безопасность

В проекте реализованы несколько механизмов, связанных с безопасностью API:

* JWT-аутентификация;
* ASP.NET Core Identity;
* авторизация защищенных endpoint'ов;
* rate limiting для чувствительных операций;
* ограничение размера загружаемых файлов;
* защита пути к файлам от path traversal;
* централизованная обработка ошибок;
* CORS.

## Rate Limiting

Для разных типов запросов используются отдельные политики.

Для авторизации действует ограничение количества запросов с одного IP-адреса.

Для загрузки файлов используется отдельный token bucket limiter.

Это позволяет снизить вероятность злоупотребления чувствительными endpoint'ами API.

## Работа с изображениями

Проект поддерживает загрузку пользовательских аватаров.

Для работы с изображениями используется **ImageSharp**.

Сохраненные аватары отдаются клиентам в формате WebP.

Для HTTP-кэширования используются:

* `ETag`;
* `Last-Modified`;
* `Cache-Control`.

## Логирование и наблюдаемость

Для логирования используется **Serilog**.

Логи могут выводиться:

* в консоль;

## Локальный запуск

### Требования

Для запуска проекта потребуются:

* **.NET 9 SDK**;
* **PostgreSQL**;
* **Redis**.

### 1. Клонировать репозиторий

```bash
git clone https://github.com/RomanGleyzer/Forum.git
cd Forum
```

### 2. Перейти в API-проект

```bash
cd src/SocialNetworkAPI
```

### 3. Настроить подключение к PostgreSQL

Рекомендуется не хранить пароли и JWT-ключи непосредственно в `appsettings.json`.

Для локальной разработки можно использовать .NET User Secrets:

```bash
dotnet user-secrets set "ConnectionStrings:PostgreSQLConnection" "Host=localhost;Port=5432;Database=socialnet;Username=postgres;Password=YOUR_PASSWORD"
```

### 4. Настроить Redis

```bash
dotnet user-secrets set "ConnectionStrings:Redis" "localhost:6379"
```

### 5. Настроить JWT

```bash
dotnet user-secrets set "Jwt:Key" "YOUR_LONG_SECRET_KEY"
```

### 6. Восстановить зависимости

```bash
dotnet restore
```

### 7. Запустить приложение

```bash
dotnet run
```

После запуска API будет доступно по адресу, указанному ASP.NET Core в консоли.

В режиме разработки документация API доступна через Swagger:

```text
/swagger
```

а состояние приложения можно проверить через:

```text
/health
```
